# 使用说明

## 1. 安装 / 启动

### 便携版

1. 解压 `入库单生成器-便携版.zip`。
2. 打开 `入库单生成器` 文件夹，双击 `入库单生成器.exe`。
3. 不要只把 exe 单独复制走，`_internal` 文件夹要和 exe 放在一起。
4. 第一次使用，点右上角 **“公司设置”**，填写入库单标题和购买方公司名称，保存即可。

不需要安装 Python；生成 Excel 不需要 Office。只有“导出 PDF 做版式检查”需要电脑装了 Excel。

### 从源码

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python app.py
```

## 2. 添加发票

三种方式任选：

- 点“添加 PDF/图片”，选一个或多个文件。
- 点“添加文件夹”，选整个发票文件夹。
- 直接把 PDF / 图片 / 文件夹**拖到左侧列表区域**（灰色提示条那里）。

添加后顶部黄色提示条会显示：

```
已添加 1 个文件：DOC004.pdf（约 20 页）— 点上方“开始识别”
```

重复添加同一路径不会重复加入。

### 公司设置（第一次使用）

点右上角 **“公司设置”**：

- **入库单标题**：显示在每张入库单顶部，例如“XX公司入库单”。
- **购买方公司名称**：识别时用来排除购买方，避免把本公司当成销售方。

点“保存”后立即生效，生成 Excel 时会用新标题，不需要改文件、不需要重启。
设置只保存在本机：

```
%LOCALAPPDATA%\Invoice2RKD\company_public.json
```

如果还没填购买方，顶部提示条会提醒先做这一步。

## 3. 识别

点顶部的绿色大按钮 **“开始识别”**（也可以按 `Ctrl+R`）。

识别模式在进度条右侧，一般保持默认：

| 模式 | 用途 |
| --- | --- |
| 自动（推荐） | 电子发票优先读 PDF 文字层；扫描件/图片走 OCR；文字层失败自动回退 |
| 仅文字层（电子票） | 只解析 PDF 文字层；扫描页会被明确跳过，适合排查电子票 |
| 仅OCR（扫描件） | 强制走 OCR，适合排查扫描件 |

识别过程中：

- 顶部进度条显示进度。
- 电子发票直接读文字层，通常比 OCR 快很多。
- 扫描件会自动旋转到正确方向，再用本地 OCR 识别。
- 程序会读取发票二维码核对发票号、日期、价税合计。
- 商品行后面的负数优惠行会自动合并成一条净额明细，不会输出负金额。
- 销售方取右侧销售方全称；购买方是“个人”时不会误当卖方。
- 费用报销单等非发票页会自动跳过。
- 同一张发票重复扫描会自动去重。

识别完成后：

- 绿色提示条：全部正常。
- 橙色提示条：有跳过页或警告，请看“日志/警告”。
- 左侧列表会显示：销售方、发票号、价税合计、项数、状态（OK / 注意）。

## 4. 核对与修改

在左侧选中一张发票，右侧切到“明细与字段”。

### 发票字段

可以直接修改：

- 销售方
- 发票号码
- 开票日期（`YYYY.MM.DD`）
- 价税合计
- 金额合计
- 税金合计
- 表名简写（工作表名前半部分）
- 到货时间 / 入库时间

改完点 **“应用发票修改”**。如果金额/税额有改动，也可以点“按明细重算合计”。

### 明细行

- 双击一行，下面的编辑框会带出该行内容。
- 改名称/规格/单位/数量/金额/税率/税金/备注，点 **“应用行修改”**。
- 点 **“添加行”** 可以补一行；点 **“删除行”** 删除当前行。
- 单位空着时，软件会尽量按项目名推断；如果不对，直接改。
- 发票里的负数优惠/折扣会自动合并到正数商品行，明细里只保留一条净额；日志会提示“优惠已合并”。

### 常见“注意”

- `第X行缺少单位`：补单位。
- `第X行数量按1处理` / 数量为空：核对发票数量。
- `明细合计与发票合计不一致`：通常是漏了一行或某行金额识别错；补行/改金额。
- `重复发票`：同一张发票被扫了两次，程序保留第一次。

## 5. 日期与月份

- 工具栏的“到货日期 / 入库日期”留空时，默认等于开票日期。
- 填了之后点“应用到全部”，会对所有发票生效。
- 年份/月份用于默认输出文件名：`2026年X月份入库单.xls`。

## 6. 生成 Excel

1. 设置输出路径（可点“浏览”或“默认路径”）。
2. 点“生成 Excel”。
3. 如果还有“注意”，会弹出提醒，确认后仍可生成。
4. 生成后会做金额自检；可选导出 PDF 做版式检查。

输出格式：

- 每张发票一个工作表。
- 表名 = 供应商简写 + 价税合计；重名时加 `-MMDD`。
- 表头：序号 / 材料名称 / 规格型号 / 单位 / 数量 / 单价 / 单价含税（隐藏）/ 金额 / 税金 / 含税价 / 到货时间 / 入库时间 / 备注。
- 合计行：金额 + 税金 = 含税价 = 发票价税合计。
- 打印设置：286 纸型（9.5×5.5 英寸）、纵向、1 页宽×1 页高、左右 0.2in / 上下 0.4in、页眉页脚为空。

如果输出文件已存在，程序会先备份一个 `.bak-时间` 文件。

## 7. PDF 版式检查

勾选/确认后，程序会用 Excel 导出 PDF，再检查：

- 页数是否等于工作表数
- 页面尺寸是否约 684×396 pt
- 是否有 `##/####` 或明显挤压

如果提示 `##/####`：

- 通常是**当前默认打印机不支持 286 纸型**。
- 把默认打印机切换为 **EPSON LQ-730K**（或支持 9.5×5.5 英寸的驱动）后再试。
- `.xls` 已经生成，打印设置已经写入，不会因为 PDF 检查失败而丢数据。

## 8. 学习历史入库单

点“学习历史入库单”，选以前入库单所在文件夹。

程序会读取 `.xls` 工作表里的供应商全称、项目名称、规格、单位，用于后续匹配：

- 供应商简写
- 项目名称补全
- 单位推断
- 规格补全

学习库保存在本机：

```
%LOCALAPPDATA%\Invoice2RKD\catalog_user.json
```

不会上传，也不会写进仓库。换电脑时需要重新学习，或把旧入库单一起带过去再学一次。

## 9. 文件和数据位置

- OCR 缓存：`%LOCALAPPDATA%\Invoice2RKD\cache\`
- 预览图：`%LOCALAPPDATA%\Invoice2RKD\cache\previews\`
- 公司设置：`%LOCALAPPDATA%\Invoice2RKD\company_public.json`
- 学习库：`%LOCALAPPDATA%\Invoice2RKD\catalog_user.json`
- 供应商简写覆盖：`%LOCALAPPDATA%\Invoice2RKD\aliases.json`
- 错误日志：`%LOCALAPPDATA%\Invoice2RKD\error.log`

删除这些文件不会影响软件启动，只会清掉缓存/学习结果。

## 10. 常见问题

**双击没反应 / 闪退**
看 `%LOCALAPPDATA%\Invoice2RKD\error.log`；首次运行被 SmartScreen 拦截时选“允许运行”。

**识别慢**
第一次要加载 OCR 模型；同一批文件第二次会走缓存。

**某些页面被跳过**
看“日志/警告”里的原因。常见：不是发票页、表格表头不完整、一页多张发票。如果识别模式选了“仅文字层”，扫描页会被跳过；改回“自动”即可。也可在界面“手动新增一张发票”或把 PDF 拆成单页。

**金额/名称有错**
电子票优先读文字层，扫描件才用 OCR；OCR 仍无法保证 100%。直接在“明细与字段”里改，改完再生成。

**公司名 / 入库单标题不对**
点右上角“公司设置”修改并保存，立即生效；不用改 `data/company.json`，也不用重启。

**电子票会不会走 OCR？**
默认不会：有完整文字层就直接解析。文字层异常/校验不通过时才会自动回退 OCR，并在日志里注明。想强制验证可切换识别模式。

**换电脑/给同事**
把整个 `入库单生成器` 文件夹复制过去；不要只复制 exe。学习库在 `%LOCALAPPDATA%`，不会跟着走，需要时可重新学习。
